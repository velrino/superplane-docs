---
title: Troubleshoot a self-hosted installation
description: Fix quota, DNS, certificate, and runner errors on a self-hosted SuperPlane installation.
---

Use this page when a self-hosted installation fails a readiness check. Collect the relevant status and logs, then match the symptom below.

## Collect single-VM diagnostics

Run these commands from the [single-VM installation directory](/self-hosting/single-vm). Check service status before reading the logs:

```bash
docker compose ps --all
docker compose logs app --tail=50
docker compose logs caddy --tail=50
docker compose --profile runners logs fleet-manager --tail=50
```

The `prepare-volumes` service can show `Exited (0)` after initialization. This is not an unhealthy application service.

If your release package contains `diagnose.sh`, use it to collect a report. This optional command requires Python 3:

```bash
./diagnose.sh
```

The command prints the private report directory and writes `summary.json` there. Use `--output /absolute/new/report_directory` to choose an unused directory. Its parent directory must already exist. The report contains status, versions, recent logs, and readiness checks without copies of environment files or private keys. Review the report before sharing it; automatic redaction cannot remove every sensitive value from application logs.

The command returns `0` when its checks pass, `1` for failed or incomplete checks, and `2` for invalid usage or prerequisites.

Public HTTPS checks validate the certificate. The `--insecure-localhost` option is only for a local test installation at `localhost` or `127.0.0.1`.

The `v1.0.0-rc7` package does not contain `diagnose.sh`. Use the manual commands above for that release. Use scripts from your selected release, not from an unrelated branch or release.

## Collect cloud-installation diagnostics

For a [Terraform cloud installation](/self-hosting/install), read the Fleet Manager log:

```bash
kubectl logs -n superplane deploy/fleet-manager-fleet-manager --tail=20
```

## Match the symptom

| Symptom | Provider | Fix |
| --- | --- | --- |
| Certificate stays pending | Single VM | Every published A and AAAA record must reach the VM on ports 80 and 443. Read the Caddy log. Follow the [DNS checks](/self-hosting/single-vm#1-configure-dns). |
| `app` is not healthy | Single VM | Run `docker compose logs app --tail=80`. `superplane.env` must set `BLOB_STORAGE_PROVIDER=filesystem`. Run `./install.sh` again. It keeps the existing secrets. |
| No runner container starts | Single VM | The installer starts the local fleet automatically. Read the Fleet Manager log and check `docker compose --profile runners ps`. A warm capacity of `0` leaves no idle runner. Check capacity and Docker access before you rerun the installer. |
| `runner version does not match` | Single VM | Rerun `./install.sh` from the verified package for your selected release. Keep its packaged image tags. The installer regenerates `fleet-manager.yaml`; do not mix component versions from different releases. |
| A required secret or OIDC key is missing or invalid | Single VM | Stop and restore the original files from a trusted backup. Do not delete the remaining configuration to generate replacement secrets. Follow [backup and restore](/self-hosting/upgrade-and-uninstall#back-up-a-single-vm). |
| The network remains in use after Compose removal | Single VM | A managed runner can remain outside Compose ownership. Follow [single-VM removal](/self-hosting/upgrade-and-uninstall#uninstall-a-single-vm). Verify exact container IDs before removal. Do not prune unrelated Docker resources. |
| Azure or AWS fleet setup fails after a new Fleet Manager chart | AWS, Azure, Google Cloud | This SuperPlane release supports Fleet Manager `@@FLEET_MANAGER_VERSION@@` and Runner `@@RUNNER_VERSION@@`. Set `image.tag` to `@@FLEET_MANAGER_VERSION@@`. Set every `runnerVersion` to `@@RUNNER_VERSION@@`. Set Helm `--version` to `@@FLEET_MANAGER_CHART_VERSION@@`. Run Helm again. |
| `SkuNotAvailable` or `NotAvailableForSubscription` | Azure | Change the region or `runner_zones`. See the region table in the install guide. |
| `QuotaExceeded` | Azure | Request quota for DDSv4 or Dpdsv6, or lower maximum capacity. A new subscription often has 4 regional vCPUs, which fits one node and one runner. |
| On-Demand vCPU limit reached | AWS | Request more Standard vCPU quota (quota code `L-1216C47A`), or lower maximum capacity. |
| `failed to load assume role` | AWS | The profile assumes a role from an `aws login` source profile. Export the CLI credentials, run `unset AWS_PROFILE`, then run plan again. See the AWS sign-in step. |
| arm64 runner fails Trusted Launch | Azure | Set `vmSize` to `Standard_D2pds_v6`. Do not use a `v5` size. Run Helm again. |
| Values file contains `<AZURE_ZONE>` | Azure | Set `zones` to `terraform output -raw runner_zones`, then run Helm again. |
| `ParameterOutOfRange: The value of the 'Version' should be in: []` | Azure | Set `create_postgresql_flexible_server = false` and apply again. |
| AMI not found, or the wizard disables a fleet | AWS | Stay in `us-east-1`. Run the image command in the install guide and set both AMI IDs to the newest match. Apply again and reload the wizard. |
| Runner image not found | Azure | Use `eastus` or `westus3` for both architectures. |
| Pods stay `Pending` | Google Cloud | Set `machine_type` to `e2-standard-2` or larger and apply again. That change replaces the cluster. |
| The page loads, then scripts fail | Google Cloud | Clear `superplane_image_tag` so the chart selects its image. A plain commit SHA is blocked on your domain. Apply again and hard-refresh. |
| `ZONE_RESOURCE_POOL_EXHAUSTED` | Google Cloud | Add zones in `runner_zones` and apply again. |
| Certificate stays pending | AWS, Azure, Google Cloud | The DNS name must be the host in `domain_name`. On AWS, `dig +short your_domain CNAME @8.8.8.8` must print the load balancer hostname. On Azure and Google Cloud, `dig +short your_domain @8.8.8.8` must print the address. |
| No runner machine appears | AWS, Azure | Run `helm list -n superplane`. Raise `maxCapacity` when every machine is busy. |
| `fleet not found` (404) once in the log | AWS, Azure, Google Cloud | Ignore that line when later lines show reconciliation. |
| `terraform destroy` stops on the load balancer | AWS | Follow the [AWS installer README](https://github.com/superplanehq/terraform/blob/v0.1.0/aws/README.md#if-traefik-or-the-internet-gateway-does-not-delete). Do not delete the Terraform state. |

A first task with warm capacity `0` waits while the machine boots. That wait is the cold start, not a failed install.
