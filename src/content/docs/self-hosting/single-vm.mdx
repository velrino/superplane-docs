Install SuperPlane on one Linux virtual machine (VM) with Docker Compose. This guide covers a public installation with automatic HTTPS.

Complete the DNS and host requirements before you start.

## Requirements

- A Linux VM with an `amd64` or `arm64` architecture.
- Administrator access to the VM.
- Docker Engine and Docker Compose v2 or later.
- Bash, cURL, tar, OpenSSL, `dig`, and `sha256sum`.
- Outbound HTTPS access to GitHub Releases, GitHub Container Registry (`ghcr.io`), and Docker Hub.
- A hostname that you control, such as `superplane.example.com`.
- Inbound TCP ports 80 and 443.

Reserve 2 vCPUs, 8 GB of memory, and 30 GB of disk for each concurrent runner. The default fleet keeps one runner ready and permits five concurrent runners.

At full capacity, the runners can use 10 vCPUs, 40 GB of memory, and 150 GB of disk. These values exclude the core SuperPlane services. Reserve additional resources for those services and account for image, log, and uploaded-file growth. Measure usage with your workload before you increase runner capacity.

For an initial installation check, use one maximum runner and one warm runner. The capacity example below sets these limits. An idle installation check does not establish capacity for production work.

## 1. Configure DNS

Create an A record for IPv4 or an AAAA record for IPv6. Point the record to the VM's public address.

If you publish both record types, point both records to the VM. Check the public records before installation:

```bash
dig +short superplane.example.com A @8.8.8.8
dig +short superplane.example.com AAAA @8.8.8.8
```

The commands must return the VM's public addresses. A blank result is valid when you do not publish that record type.

If DNS returns multiple addresses, each address must reach the VM on ports 80 and 443.

## 2. Download the release

Connect to the VM. Download the archive and checksum file from the same release:

```bash
VERSION=@@SUPERPLANE_IMAGE_TAG@@
curl -fsSL -o superplane-single-host.tar.gz \
  "https://github.com/superplanehq/superplane/releases/download/${VERSION}/superplane-single-host.tar.gz"
curl -fsSL -o checksums.txt \
  "https://github.com/superplanehq/superplane/releases/download/${VERSION}/checksums.txt"
grep ' superplane-single-host.tar.gz$' checksums.txt | sha256sum --check
```

The checksum command must report `superplane-single-host.tar.gz: OK`. If it fails, stop. Download the files again before installation.

Extract the verified archive:

```bash
tar -xzf superplane-single-host.tar.gz
cd superplane
```

The release uses Fleet Manager `@@FLEET_MANAGER_VERSION@@` and Runner `@@RUNNER_VERSION@@`. Keep the component versions packaged with your selected SuperPlane release. Do not replace them with newer tags independently.

## 3. Install SuperPlane

Run the installer from the extracted `superplane` directory. This example limits the installation to one maximum runner and one warm runner:

```bash
SUPERPLANE_RUNNER_MAX_CAPACITY=1 \
SUPERPLANE_RUNNER_WARM_CAPACITY=1 \
./install.sh
```

Enter the hostname when the installer asks for it. Do not include `https://`.

The installer also requests an HTTPS certificate for the hostname.

The installer starts Fleet Manager and the local runner fleet. Fleet Manager uses the Docker socket to start runner containers.

Set different capacity values before you run the installer if your host supports more runners. The maximum capacity must be a positive integer. The warm capacity must be between zero and the maximum capacity.

The installer generates `superplane.env`, `fleet-manager.env`, `rabbitmq.env`, `fleet-manager.yaml`, and the keys in `oidc/`. The archive does not contain these installation-specific files. Configure capacity through the supported environment variables. The installer can regenerate `fleet-manager.yaml` and `rabbitmq.env` when you run it again.

<Aside type="caution">
The generated environment files and `oidc/` contain secrets. Restrict access to the installation directory. Follow the [backup procedure](/self-hosting/upgrade-and-uninstall#back-up-a-single-vm) before maintenance.

Fleet Manager can control Docker through the host socket. Install SuperPlane only on a VM that you administer.
</Aside>

## 4. Verify the installation

Check the services and the health endpoint:

```bash
docker compose ps --all
curl -fsS -o /dev/null -w '%{http_code}\n' \
  "https://superplane.example.com/health"
```

Long-running services must show `running` or `healthy`. The `prepare-volumes` initialization service can show `Exited (0)` after success. The health command must print `200`.

If a check fails, use [Troubleshooting](/self-hosting/troubleshooting).

## 5. Create the owner account

Open `https://superplane.example.com/setup`.

<Steps>

1. On **Create the owner account**, enter the name, email, and password. The password needs 8 or more characters, one number, and one capital letter.

   Review the optional owner-details sharing checkbox. Clear it if you do not want to share those details. Select **Continue**.

## 6. Next steps

After owner setup, the application opens workspace onboarding. Continue on your installation hostname with the [quickstart](/get-started/quickstart). Do not create a second account on the hosted service for this installation.

If the installation fails, use [Troubleshooting](/self-hosting/troubleshooting). Use [Upgrade and uninstall](/self-hosting/upgrade-and-uninstall) to manage the installation.
